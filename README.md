# HH Requirements Export

Python-скрипт для выгрузки вакансий с hh.ru по пользовательскому поисковому запросу через официальный API HeadHunter. Скрипт получает поисковую выдачу, загружает полную карточку каждой вакансии, очищает HTML-описание, эвристически выделяет блоки требований/обязанностей/условий и сохраняет результат в Excel и/или CSV.

## Возможности

- поиск вакансий по текстовому запросу;
- фильтрация по региону, зарплате, валюте, графику, опыту и области поиска;
- загрузка детальной карточки вакансии по ID;
- корректная обработка отсутствующих зарплат, навыков, работодателя, региона и описания;
- очистка HTML с сохранением читаемой структуры списков;
- извлечение блоков `requirements_from_description`, `responsibilities_from_description`, `conditions_from_description`;
- сохранение результата в `.xlsx`, `.csv` или оба формата;
- логирование в консоль и файл `logs/hh_parser.log`;
- устойчивость к временным ошибкам API и пропуск проблемных вакансий без остановки всей выгрузки;
- передача корректных заголовков `User-Agent` и `HH-User-Agent`, а также опционального OAuth-токена для запросов к API.

## Установка

Требуется Python 3.10 или выше.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Для Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Быстрый запуск

```powershell
python hh_requirements_export.py --text "менеджер маркетплейсов" --area 113 --pages 5 --per-page 50 --out output/hh_marketplace_manager.xlsx
```

Скрипт автоматически создаст папки `output` и `logs`, если они отсутствуют.

Если API возвращает `403 Forbidden`, укажите контактный User-Agent в формате `ИмяПриложения/версия (email)` и, при необходимости, OAuth-токен:

```powershell
$env:HH_USER_AGENT = "hh-requirements-export/1.0 (you@example.com)"
$env:HH_ACCESS_TOKEN = "ваш_access_token"
python hh_requirements_export.py --text "менеджер маркетплейсов" --area 113 --pages 2 --per-page 20 --out output/hh_marketplace_manager.xlsx
```

Эти же значения можно передать аргументами `--user-agent` и `--access-token`.

## Интерактивный запуск без параметров

Если запустить файл без аргументов из PowerShell, CMD или IDE, скрипт перейдёт в интерактивный режим и попросит ввести обязательные значения:

```powershell
python hh_requirements_export.py
```

Сначала нужно ввести поисковый запрос `--text`, затем путь к выходному файлу `--out`. Для файла можно нажать Enter — тогда будет создан путь по умолчанию в папке `output`, например `output/менеджер_маркетплейсов_20260609_120000.xlsx`. Остальные параметры будут взяты из значений по умолчанию.

## Примеры сценариев

### 1. Выгрузить требования по менеджеру маркетплейсов

```powershell
python hh_requirements_export.py --text "менеджер маркетплейсов" --area 113 --pages 5 --per-page 50 --out output/hh_marketplace_manager.xlsx
```

### 2. Выгрузить только вакансии с зарплатой

```powershell
python hh_requirements_export.py --text "менеджер маркетплейсов" --area 113 --pages 5 --per-page 50 --only-with-salary --out output/hh_marketplace_salary.xlsx
```

### 3. Искать по описанию вакансии

```powershell
python hh_requirements_export.py --text "wildberries ozon аналитика продаж" --area 113 --pages 5 --per-page 50 --search-field description --out output/hh_marketplace_description.xlsx
```

### 4. Сохранить Excel и CSV одновременно

```powershell
python hh_requirements_export.py --text "аналитик маркетплейсов" --area 113 --pages 2 --per-page 20 --output-format both --out output/hh_marketplace_analyst.xlsx
```

## Параметры командной строки

| Параметр | Обязательный | Значение по умолчанию | Описание |
| --- | --- | --- | --- |
| `--text` | да, кроме интерактивного режима | — | Поисковый запрос, например `"менеджер маркетплейсов"`. |
| `--out` | да, кроме интерактивного режима | — | Путь к выходному файлу. Расширение корректируется под выбранный формат; при интерактивном запуске можно принять путь по умолчанию. |
| `--area` | нет | `113` | Регион поиска в справочнике hh.ru. `113` — Россия. |
| `--pages` | нет | `5` | Количество страниц поисковой выдачи. |
| `--per-page` | нет | `50` | Количество вакансий на странице. API hh.ru принимает значения от 1 до 100. |
| `--search-field` | нет | не задано | Область поиска: `name`, `company_name` или `description`. |
| `--only-with-salary` | нет | `False` | Искать только вакансии с указанной зарплатой. |
| `--currency` | нет | не задано | Валюта зарплаты для фильтра API, например `RUR`. |
| `--schedule` | нет | не задано | График работы в формате справочника hh.ru, например `remote`. |
| `--experience` | нет | не задано | Опыт работы в формате справочника hh.ru, например `between1And3`. |
| `--output-format` | нет | `xlsx` | Формат выгрузки: `xlsx`, `csv` или `both`. |
| `--delay` | нет | `0.3` | Пауза между запросами к API в секундах. |
| `--user-agent` | нет | переменная `HH_USER_AGENT` или встроенное значение | Значение для заголовков `User-Agent` и `HH-User-Agent`. Рекомендуемый формат: `ИмяПриложения/версия (email)`. |
| `--access-token` | нет | переменная `HH_ACCESS_TOKEN` | OAuth access token для авторизованных запросов, если API требует авторизацию. |
| `--debug` | нет | `False` | Подробное логирование параметров и HTTP-запросов. |

## Колонки выходного файла

Одна строка соответствует одной вакансии.

| Колонка | Описание |
| --- | --- |
| `vacancy_id` | ID вакансии на hh.ru. |
| `name` | Название вакансии. |
| `employer_name` | Название работодателя. |
| `area_name` | Город или регион. |
| `salary_from` | Зарплата от. |
| `salary_to` | Зарплата до. |
| `salary_currency` | Валюта. |
| `salary_gross` | `True`, если сумма указана до вычета налогов. |
| `experience` | Требуемый опыт. |
| `employment` | Тип занятости. |
| `schedule` | График работы. |
| `published_at` | Дата публикации вакансии. |
| `alternate_url` | Ссылка на вакансию. |
| `key_skills` | Ключевые навыки через запятую. |
| `snippet_requirement` | Краткие требования из поисковой выдачи. |
| `snippet_responsibility` | Краткие обязанности из поисковой выдачи. |
| `requirements_from_description` | Извлечённый блок требований из полного описания. |
| `responsibilities_from_description` | Извлечённый блок обязанностей из полного описания. |
| `conditions_from_description` | Извлечённый блок условий из полного описания. |
| `full_description_text` | Полное очищенное описание вакансии. |
| `source_query` | Поисковый запрос, по которому найдена вакансия. |
| `loaded_at` | Дата и время выгрузки. |

## Как извлекаются требования

API hh.ru не всегда отдаёт требования отдельным структурированным полем, поэтому скрипт применяет эвристику:

1. очищает HTML-описание вакансии;
2. ищет заголовки вроде `Требования`, `Мы ожидаем`, `Кого мы ищем`, `Необходимые навыки`, `Будет плюсом`;
3. забирает текст после найденного заголовка до следующего смыслового блока, например `Обязанности`, `Условия`, `О компании`;
4. если отдельный блок не найден, оставляет `requirements_from_description` пустым, но сохраняет `snippet_requirement`, `key_skills` и `full_description_text` для ручного анализа.

## Логи

Лог пишется в консоль и в файл:

```text
logs/hh_parser.log
```

В лог попадают параметры запуска, страницы поиска, количество вакансий, ID обрабатываемых вакансий, ошибки API/данных, итоговое количество обработанных и пропущенных вакансий.

## Возможные ошибки и решения

| Ошибка | Что делать |
| --- | --- |
| `Нет подключения к интернету или api.hh.ru недоступен` | Проверьте интернет и доступность `https://api.hh.ru`. |
| `403 Client Error: Forbidden` | Укажите `HH_USER_AGENT`/`--user-agent` в формате `ИмяПриложения/версия (email)`. Если в тексте ошибки API есть `oauth`, передайте актуальный токен через `HH_ACCESS_TOKEN` или `--access-token`. В новых логах скрипт выводит детали ответа API и `request_id`, если они пришли от hh.ru. |
| `Превышен лимит запросов` | Увеличьте `--delay`, уменьшите `--pages` или повторите запуск позже. |
| `--per-page должен быть от 1 до 100` | Укажите допустимое значение `--per-page`. |
| В колонке `requirements_from_description` пусто | Это допустимо: описание вакансии могло не содержать отдельный блок требований. Проверьте `snippet_requirement`, `key_skills` и `full_description_text`. |
| Некоторые вакансии пропущены | Вакансии могли быть удалены, закрыты или временно недоступны. Подробности есть в `logs/hh_parser.log`. |

## Проверочный запуск

Для короткой проверки можно выполнить:

```powershell
python hh_requirements_export.py --text "менеджер маркетплейсов" --area 113 --pages 2 --per-page 20 --out output/test_marketplace.xlsx
```

Ожидаемый результат: файл `output/test_marketplace.xlsx` создан, вакансии загружены, ссылки сохранены, отсутствующие данные не приводят к падению скрипта, в консоли показан итог выполнения.
